# Tibero GIS 공간 데이터 처리 라이브러리 모듈화 및 개발

**기술 Stack**: C++, C, WKB, 자체 Memory Allocator, PostGIS/Oracle Spatial 호환
**소속**: Tmax Tibero · GIS 엔진팀 (2023.01–06)

## 개요 (Overview)

기존 DBMS(Tibero) C 엔진 내부에 인라인 형태로 산재되어 있던 GIS 코드를 독립적인 C++ 라이브러리로 분리하고 모듈화하는 작업을 진행했습니다. GIS 데이터 처리를 C++ 기반 프레임워크로 이식하여 구조를 개선하였으며, 자체 할당자 기반의 GIS 메모리 처리 엔진(vec2/3/4 좌표 차원 대응) 및 ST_ 계열 공간 함수의 설계를 담당하여 Tibero 7의 공간 데이터 기능 확장의 기반을 마련했습니다.

## 주요 아키텍처 및 해결 과제 (Key Architecture & Technical Challenges)

- **레거시 코드 분리 및 C++ 모듈화**: C 엔진 내부의 결합도가 높은 인라인 코드를 정제하고 독립 라이브러리로 이식했습니다. 이를 통해 응집도를 높이고 의존성을 분리하여 GIS 기능의 장기적인 유지보수성과 확장성을 개선했습니다.
- **다차원 좌표 데이터 모델 처리**: 2차원 공간 좌표(XY)뿐만 아니라 고도(Z)와 선형 참조(M) 정보가 포함된 3차원 및 4차원 좌표 차원(vec2/vec3/vec4)에 대응하는 구조를 설계했습니다. WKB(Well-Known Binary) 표준 포맷과의 호환성을 갖추어 공간 데이터 인프라의 표준 스펙을 준수했습니다.
- **공간 데이터 전용 메모리 할당자 설계**: 대용량 GIS 연산의 특성을 고려하여, 잦은 동적 할당/해제 오버헤드를 제어하기 위해 전용 메모리 할당자(Memory Allocator)를 연동했습니다. 이를 통해 빈번한 시스템 콜 호출을 제어하고 실시간 동작 시의 메모리 누수 원인을 제거했습니다.

## 기여도 및 주요 성과 (Contributions & Achievements)

- **공간 함수 대량 확장 기반 마련**: 모듈화 작업을 통해 Tibero 7 버전에서 공간함수 기능을 확장할 수 있는 아키텍처 기반을 정립했습니다. (Tibero 6 버전의 ST_ 함수 63개 대비 Tibero 7.2.5 버전에서 80개 이상으로 대폭 확장)
- **독립 메모리 관리 구조 설계**: 자체 Allocator 기반의 GIS 메모리 처리 아키텍처와 다차원 좌표계 분기 처리를 전담 구현하여, 라이브러리의 완성도와 메모리 안정성을 확보했습니다.
