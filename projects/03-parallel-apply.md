# 대용량 트랜잭션 병렬 반영 최적화

**기술 Stack**: C, Multithreading, WAL(Write-Ahead Logging), Connection Pool, Red-Black Tree, SQL Batch Update
**소속**: Tmax Tibero · 데이터 동기화 엔진팀

## 개요 (Overview)

기존 단일 스레드 기반 트랜잭션 직렬 반영 아키텍처의 한계를 극복하고, 데이터 무결성과 순서 정합성을 유지하면서 처리량을 향상시키기 위해 멀티스레드 병렬 반영 아키텍처를 설계했습니다. 대용량 트랜잭션 유입 시의 병목을 제어하고자 스레드 풀 기반의 데이터베이스 커넥션 구조를 도입했으며, 트랜잭션 간 종속성을 판별하는 스케줄링 로직을 개발했습니다. 의존성 확인용 메모리 자료구조를 최적화하고 SQL 일괄 처리(Batch Update)를 유기적으로 연동하여 상용 서비스 환경에 적합한 성능과 리소스 예측 가능성을 확보했습니다.

## 주요 아키텍처 및 해결 과제 (Key Architecture & Technical Challenges)

- **의존성 기반 병렬 트랜잭션 스케줄러**: WAL(Write-Ahead Logging) 로그 분석 레이어에서 커밋 예정 트랜잭션들 간의 데이터 종속성을 실시간 판별하고, 상호 간섭이 없는 독립 트랜잭션들을 멀티스레드 반영 큐로 분배하여 정합성 깨짐 없이 병렬 반영 처리가 가능하게 했습니다. (반영 단위를 Object 및 Row 모드로 세분화하여 제어)
- **자료구조의 기술적 선택 및 검증 (Hash Map vs Red-Black Tree)**:
  - **해시 맵의 가상 메모리 과점유 극복**: 반영 대상 행의 고유 식별자인 `rowid` 판별에 해시 맵 구조를 대안으로 검토했으나, rowid의 랜덤 분산 특성으로 인해 버킷 충돌 방지 차원에서 약 1억 개 규모의 대역 버킷을 유지해야 했고, 이는 데이터 실제 탑재량과 상관없이 상시 약 6GB 이상의 메모리를 무단 점유해야 하는 오버헤드를 발생시켰습니다.
  - **Red-Black Tree 기반 동적 리소스 관리**: 실제 유입되는 액티브 트랜잭션 규모에만 정비례해 동적으로 메모리 노드를 관리하는 **Red-Black Tree** 자료구조를 주도적으로 선택하고 이식했습니다. 이를 통해 불필요한 고정 가상 메모리 점유를 억제하고, 해시 맵의 버킷 확장(Rehashing) 시 동반되는 동시성 지연 스파이크(Latency Spike)를 통제했습니다.
- **SQL Batch Update 최적화**: 대량 쓰기 상황에서 타겟 DB에 가해지는 질의 횟수를 최소화하기 위해 SQL 배치 전송 방식을 통합 개선하여 네트워크 입출력 구간의 누적 대기 오버헤드를 축소했습니다.

## 기여도 및 주요 성과 (Contributions & Achievements)

- **처리 성능 향상**: 병렬 반영 흐름 제어와 효율적 스케줄링을 통해 대용량 부하 집중 상황에서 최대 16배(스레드 비례), 일반 트랜잭션 처리 상황에서도 통상 2~3배 수준의 성능 개선을 달성했습니다.
- **예측 가능한 시스템 자원 운영**: Red-Black Tree 적용을 통해 가용한 메모리 점유 상한을 구조적으로 예측할 수 있게 만들어, 가상 메모리 급증 리스크를 해결하고 상용 사이트 프로덕션 환경에 안정적으로 배포했습니다.
