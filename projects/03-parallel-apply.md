# 대용량 트랜잭션 병렬 반영 최적화

**기술 Stack**: C, Multithreading, WAL(Write-Ahead Logging), Connection Pool, Red-Black Tree, SQL Batch Update
**소속**: Tmax Tibero · 데이터 동기화 엔진팀

## 개요 (Overview)

기존의 단일 데이터베이스 커넥션 및 단일 스레드 기반 트랜잭션 직렬 반영 구조를 탈피하여, 데이터의 무결성과 순서 정합성을 엄격하게 유지하면서 반영 처리량을 극대화하는 멀티스레드 병렬 반영 아키텍처를 구축하였습니다. 대용량 트랜잭션 부하 상황에서의 심각한 병목 현상을 해결하고자 최대 16개 스레드를 운용하는 커넥션 풀 구조를 도입하였으며, 각 트랜잭션 간 및 내부 DML 문 간의 데이터 의존성을 정밀하게 확인하는 의존성 판별 및 병렬 스케줄링 메커니즘을 설계하였습니다. 또한 대량의 트랜잭션 반영 정보를 판별하는 고효율 메모리 자료구조를 재배치하고 SQL 일괄 처리(Batch Update)를 최적화하여 상용 수준의 우수한 성능과 높은 메모리 예측 가능성을 확보하였습니다.

## 주요 아키텍처 및 해결 과제 (Key Architecture & Technical Challenges)

- **트랜잭션 의존성 분석을 통한 병렬 스케줄링**: WAL(Write-Ahead Logging) 직렬화 모듈에서 대기 중인 커밋 트랜잭션들과 내부 DML 간의 데이터 종속성을 정밀하게 평가하여, 상호 영향이 없는 독립 트랜잭션을 식별하고 이를 스레드 풀에 할당함으로써 정합성을 지키면서도 최대의 병렬성으로 처리량을 높였습니다. (반영 단위에 대해 Object 모드 및 Row 모드를 동시에 지원)
- **자료구조의 기술적 선택 (Hash Map vs Red-Black Tree)**:
  - **메모리 효율성의 한계 극복**: 동기화 반영 단위 판별의 핵심 식별자인 `rowid`는 해시 맵 적용 시 난수성 분포 특징으로 인해 버킷 충돌 위험이 크고, 이를 해결하기 위해 대형 버킷(약 1억 개 규모)을 설계할 경우 메타데이터 포인터 오버헤드로 인해 실데이터 유무와 무관하게 상시 6GB 이상의 과도한 가상 메모리를 강제 점유해야 하는 한계가 존재했습니다.
  - **예측 가능한 리소스 제어**: 대신 실제 트래픽 분량만큼만 동적으로 메모리를 할당하는 `rowid` 정렬 기반의 **Red-Black Tree** 자료구조를 도입하였습니다. 이를 통해 O(N) 재해싱 작업 시 발생하는 인스턴스 지연 스파이크(Latency Spike)를 제거하고, 메모리 예측성이 필수적인 상용 동기화 솔루션 스펙에 완벽히 부합하도록 구현하였습니다.
- **데이터베이스 반영 입출력 최적화**: 대량 트래픽 조건 하에서 타겟 데이터베이스로 유입되는 SQL 쿼리 처리 횟수를 최소화하기 위해 SQL Batch Update 로직을 개선함으로써, DB 드라이버 단의 입출력 병목 현상을 추가적으로 줄였습니다.

## 기여도 및 주요 성과 (Contributions & Achievements)

- **극적인 병목 해소 및 고대역폭 데이터 처리**: 트래픽 부하 분산 및 정합성 검사 기법 도입으로 대용량 병목 상황에서 최대 16배(스레드 한도 비례), 일반 트래픽 조건하에서도 통상 2~3배 이상의 성능(Throughput) 개선을 입증하였습니다.
- **예측 가능하고 균일한 시스템 가용성 유지**: Red-Black Tree 적용을 통한 예측 불가능한 메모리 누출 및 오버헤드 억제 기법을 입증하여 제품의 장기 구동 안정성을 입증하였으며, 다수의 실고객사 상용 노드 배포에 성공하였습니다.
