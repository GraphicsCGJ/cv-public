# 클러스터 HA 기반 동기화 엔진 Failover 설계·검증·배포

기술: C, TBCM(클러스터 관리), Shared Storage
소속: Tmax Tibero · 데이터 동기화 엔진팀

## 330자판 (316자)

```
[목표/배경]
대규모 멀티노드 사이트에선 노드·프로세스 장애에도 동기화가 끊기지 않아야 했고, 회사 클러스터 관리(TBCM, Pacemaker 유사)의 HA 위에서 동기화 엔진 장애 대응을 완결하는 게 목표였습니다.
[역할·수행]
기존 클러스터 HA에 동기화 엔진을 연동하고, 엔진·클러스터 관리자가 죽는 등 장애 시나리오를 도출해 상황별 Failover 동작을 설계·검증했습니다.
[성과·기여도]
사내·고객사 검증을 통과시키고 배포까지 주도해, 대규모 고객사 프로덕션에 무중단 적용되어 운영 중입니다. (개인 기여도 약 70% — 시나리오 설계·검증·배포 주도)
```

## 메모 (정직한 실제 그림)

- HA 자체를 새로 만든 게 아님. 회사 메인 엔진인 클러스터 관리(TBCM)가 네트워크 스토리지 위에서 HA를 제공 (Pacemaker/TAC 유사). 그 위에 동기화 엔진 기능을 얹은 것.
  - 비유: "Pacemaker를 통해 HA를 이뤄냈다"와 유사한 구조.
- 내 실제 기여 = 설계·검증·프로덕션화:
  1. 장애 시나리오 전부 도출 — ProSync가 죽었을 때 / TBCM이 죽었을 때 등 시나리오별 동작 정리
  2. 고객사(KT)에 설명·납득
  3. 사내 테스트 + KT 내부 테스트 통과
  4. 실제 배포 → 현재 KT 프로덕션에서 운영 중
- KT는 CV엔 "대규모 고객사"로, 면접에서 구두로.
- 강점: 설계→고객 검증→프로덕션까지 end-to-end 오너십 + 실제 대형 고객사 운영 중.
